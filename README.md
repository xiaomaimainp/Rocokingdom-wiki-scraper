# 洛克王国世界 Wiki 图鉴爬虫（Rocokingdom-wiki-scraper）

基于 [Scrapling](https://github.com/D4Vinci/Scrapling) 的洛克王国世界 B 站 wiki（nrc）图鉴爬虫，用于抓取**精灵图鉴**、**技能档案**、**技能来源 / 获取条件**、**进化链**、**图鉴课题（技能石）**与**特性图鉴**，并生成合并表与精灵技能总表。

相比传统 `requests + BeautifulSoup`，使用 `Fetcher` / `StealthyFetcher` 自动伪装 TLS 指纹与请求头，抗反爬能力更强；详情页抓取采用并发 Spider 框架（`ThreadPoolExecutor` + 退避重试 + 失败串行补抓），速度更快、更稳。

> 本站只抓新版 wiki：`https://wiki.biligame.com/nrc/`。旧站 `rocom`（数据截至 S3）相关代码与参数已全部移除。

## 环境要求

- Python 3.10+（当前基于 Scrapling 0.5.1，实测 Python 3.14 可用）
- 需要 patchright 的 chromium（`StealthyFetcher` 兜底抓取使用）

### 安装依赖

```bash
pip install "scrapling[fetchers]==0.5.1"
scrapling install                        # 安装 Scrapling 的浏览器依赖
python -m patchright install chromium    # 下载 patchright 专用 chromium（StealthyFetcher 用）
```

> 注意：`scrapling install` 不会安装 patchright 专用 chromium，两者都要执行，否则 `StealthyFetcher` 会报浏览器缺失。

### 升级 Scrapling

```bash
python -m pip install --upgrade "scrapling[fetchers]==0.5.1" -i https://pypi.org/simple
scrapling install --force
python -m patchright install chromium
```

> 清华镜像源目前没有该包，需指定官方源；升级 `patchright` 后必须重新下载对应版本的 chromium。0.5 的破坏性变更（`DynamicFetcher` / `cdp_url` / `capture_xhr` / `keep_cdata`）本项目均未使用，升级不需要改脚本。

## 使用方法

在脚本所在目录运行：

```bash
# 抓取 → 合并 → 复检（覆盖更新；连续两次抓不到才淘汰）
python nrc_scraper.py

# 只体检已有数据文件，不联网
python nrc_scraper.py check

# 不联网，用已有 CSV 重算合并表与「技能石课题」列
python nrc_scraper.py rebuild

# 抓取「图鉴课题」聚合页，生成技能石清单 skill_stones.csv（一次静态请求覆盖全部有课题的物种）
python nrc_scraper.py skillstones

# 用聚合页交叉验证主爬取的技能石课题（按序号比对差异）
python nrc_scraper.py validate

# 抓取「特性图鉴」生成 features_data.csv，并给精灵图鉴补「特性」「特性介绍」两列
# （一次静态请求即可，不重抓 662 个精灵页，也不写快照）
python nrc_scraper.py features

# 不联网，统一 skill_sources.csv 的「来源类型」「等级」写法
python nrc_scraper.py normalize

# 抓全部精灵页，生成 skill_catalog.csv（每行一个可学技能，含血脉属性）
python nrc_scraper.py skillcatalog
```

- 第一次没有数据也能直接跑，会全量建立（首次运行不淘汰任何记录）；
- **不是纯增量**：每次运行都以本次抓取为准覆盖已有字段、追加新条目；旧条目连续两次都没抓到才从表中移除，差异报告会打印与上次的对比；
- 精灵 / 技能 / 来源 / 技能石 / 进化链 / 特性 / 技能总表七张表都走这套策略，`combined_data.csv` 作为派生视图随技能石清单重算；
- `update` 会同时刷新技能石清单、特性表、技能总表、进化链、合并表与「技能石课题」「特性」「特性介绍」列，并自动过滤 `???` 等未公开占位条目；
- 每次 `update` 会在 `.snapshots/` 保存本次抓取的记录键集合，只保留最近 2 份作为淘汰判定的基底（目录已加入 `.gitignore`）；没有基底时不会删除任何历史记录。

## 合并表格式（combined_data.csv）

目标列：`序号, 精灵名称, 属性, 技能名称1, 技能名称2, 技能名称3, 条件`

- 每个精灵最多展示 **3 个**技能石技能。
- `条件` 列 = 该精灵每个技能石技能的获取条件用分号加空格拼接，例如 `使用1次闪光; 使用1次光刃`。
- **以官方「图鉴课题」聚合页为准，一个序号（物种）一行**：
  - 分支形态（如 `191` 的「棋祈督 / 棋契陛下」）**不再拆成重复行**，`精灵名称` 取官方页的物种名；
  - 技能归属与官方一致（如 `189 棋骑士 = 缠丝劲 / 截拳`），不会错归到其他序号；
  - `属性` 取自精灵表该序号的主属性。
- 没有技能石课题的精灵不出现在该表；663 个精灵形态中只有 214 个有课题的序号进表（2026-11-13）。

示例：

```csv
序号,精灵名称,属性,技能名称1,技能名称2,技能名称3,条件
001,迪莫,光,闪光,光刃,,使用1次闪光; 使用1次光刃
010,水灵,水,水炮,潮汐,,使用2次水炮; 使用2次潮汐
011,鸭吉吉,普通,防御,吓退,伺机而动,使用1次防御; 使用1次吓退; 使用1次伺机而动
```

## 进化链格式（evo_chains.csv）

目标列：`家族, 分支, 阶序, 源精灵, 源精灵序号, 目标精灵, 目标精灵序号, 进化条件, 是否特殊`

- 每行 = 一条进化步骤（`源精灵` → `目标精灵`）。同一家族的所有形态会铺开成多行；`家族` 取进化链最底层的那个精灵。
- `分支`：新模板取 `data-sd-p-evo-branch`、旧模板取 `data-branch`（普通线性进化都是 `1`；存在分支进化时会出现 `2`、`3`…）。
- `阶序`：来源形态的阶位标签，如 `初阶 · 冰`。
- `源精灵序号` / `目标精灵序号`：对应精灵在 `spirits_data_all.csv` 中的 `序号`（图鉴主 key）。进化链里的精灵名可能带「（…）」形态后缀，而 `spirits_data_all.csv` 中同名精灵常以形态后缀区分，因此这里按「基础名（忽略形态后缀）→ 序号」对齐，方便用序号直接关联两张表；对齐不上的会在体检中报「按序号找不到」。
- `进化条件`：进化所需条件文本，例如 `LV28 突破1次`、`LV40 生涯使用[滚雪球]15次`。
- `是否特殊`：**是** = 该家族存在分支进化（分支数 > 1），或任一进化步骤的条件**不是纯等级进化**。只有「`LVx`」或「`LVx 进化`」这类纯等级进化算**否**（普通）；突破（`LVx 突破y次`）、天气/时间、性别（雌性）、技能使用（生涯使用[X]N次）、道具（信物首领化）等附加条件一律算 **是**（特殊）。

示例：

```csv
家族,分支,阶序,源精灵,源精灵序号,目标精灵,目标精灵序号,进化条件,是否特殊
小雪人,1,初阶 · 冰,小雪人,354,雪怪,355,LV40 生涯使用[滚雪球]15次,是
钨丝贝贝,1,初阶 · 机械,钨丝贝贝,348,辉光幕机,349,LV28 突破1次,是
钨丝贝贝,1,二阶 · 机械,辉光幕机,349,机幕方舟,350,LV40 突破2次,是
```

> 解析自每个精灵页的「进化链」面板：新模板 `.sd-p-evo-group` / `.sd-p-evo-chain`，旧模板 `.roco-evo-wrap` / `.roco-evo-timeline`，解析器两套兼容。一个家族的完整链在任意成员页都能拿到，脚本按家族去重，只保留一次；当前共 229 个家族 / 455 条步骤（2026-11-13）。

## 特性图鉴格式（features_data.csv）

一行一个特性，2026-11-13 共 259 行（有 1 组同名特性，靠 `特性编号` 区分）：

| 列 | 说明 |
| --- | --- |
| `特性编号` | 页面自带的 6 位编号（如 `200191`），作为合并键 |
| `特性名称` / `特性介绍` | 特性名与效果文本 |
| `主属性` / `副属性` | 特性分类（`data-feature-*-type`） |
| `拥有精灵数` | 页面上 `.nrc-feature-card-owner-avatar` 的个数（合计 662） |
| `拥有精灵` | 拥有者名字，分号分隔；从 `data-skill-catalog-text` 尾部解析，个数与头像数不符时置空 |

精灵图鉴新增的 `特性` / `特性介绍` 两列由这张表的「拥有精灵」反向填入：先按全名精确匹配，再按基础名（忽略形态后缀）兜底，因此带「（…）」后缀的形态也能拿到对应特性；663 行全部命中（2026-11-13）。

## 技能总表格式（skill_catalog.csv）

每行 = 一个精灵的一个可学技能，2026-11-13 共 32840 行 / 662 个精灵。用来跟踪版本改动后「某精灵的血脉技能 / 可学技能被替换」的情况。

| 列 | 说明 |
| --- | --- |
| `精灵名称` / `技能名称` / `技能ID` | 精灵名、技能名、页面 `data-sd-p-skill` 里的 ID（如 `skill_000274`） |
| `来源类型` / `学习等级` | 自学 / 技能石 / 血脉 / 传说；等级统一为纯数字（技能石 `999`、血脉 `15`） |
| `血脉属性` | **仅血脉技能有值**，如 `普通血脉` / `草血脉`；取自 `.sd-p-learning`（`普通血脉 · Lv.15`），共 18 种、11916 行 |
| `技能系别` / `技能类别` | 系别（电系…）、类别（物攻 / 魔攻 / 防御 / 状态） |
| `威力` / `能耗` / `技能描述` | `data-power=-1` 表示无威力，写空；效果文本取自 `.sd-p-skill-description` |
| `顺序` | 页面 `data-order`，保留原始展示顺序 |

数据来自精灵详情页 `.sd-p-skill-card`（复用来源表那次抓取，不额外发请求）；建键 `(精灵名称, 技能名称, 来源类型)`，接入「覆盖更新 + 两次缺失淘汰」，旧技能被换掉后会淘汰、新技能会追加。`skillcatalog` 模式按精灵整体替换（抓不到的精灵沿用旧数据），`update` 也会同步刷新。

## 实现要点

### 合并策略（`merge_table` / 快照基底）

纯增量会让「wiki 已经改掉的内容」永远留在表里（例如某只精灵的血脉技能被换成另一个技能）。因此 `update` 以**本次抓取为准**，并用最近两次快照做缓冲：

| 情况 | 处理 |
| --- | --- |
| 本次抓到，旧表已有 | **逐字段用本次值覆盖**；本次值为空时保留旧值（防限流简化页把好数据洗成空） |
| 本次抓到，旧表没有 | 追加 |
| 本次没抓到，上一份快照里有 | 暂留观察，判定为疑似限流 |
| 本次和上一份快照都没有 | **连续两次缺失 → 从主表移除** |
| 首次运行（无上一份快照） | 只更新 / 追加，不删除任何记录 |

- 快照：`.snapshots/snapshot_<纳秒时间戳>.json`，记录本次抓到的键集合，只保留最近 2 份（已被 `.gitignore` 忽略）。
- 建键方式（`TABLE_KEYS`）：精灵 `(序号, 名称)`、技能 `(技能名称)`、来源 `(精灵名称, 技能名称)`、技能石 `(序号, 条件)`、进化链 `(家族, 分支, 源, 目标, 条件)`、特性 `(特性编号)`、技能总表 `(精灵名称, 技能名称, 来源类型)`。来源表与技能总表都按技能建键，所以血脉技能被改掉时，旧技能会淘汰、新技能会追加。
- 应用范围：精灵表、技能表、来源表、技能石表、进化链、特性表、技能总表；`combined_data.csv` 由技能石清单派生，随其重算。
- 保护：技能详情页抓取失败时沿用旧记录，不被误判为「wiki 删除」；进化链整轮为空时保留上次数据并跳过淘汰判定，避免模板改版清空整表。
- 日志里的 `[本次缺失]` 只表示这一次没读到，要连续两次才淘汰；合并统计会打印「更新 / 新增 / 待观察 / 淘汰」条数。

### 特性图鉴（`crawl_features` / `mark_traits`）
- 特性图鉴页是静态卡片：`.nrc-feature-catalog-card`（259 张），名称在 `.nrc-skill-catalog-card-name`、介绍在 `.nrc-feature-card-description`、拥有者头像在 `.nrc-feature-card-owner-avatar`；
- 拥有者名字藏在 `data-skill-catalog-text`（「特性名 介绍 编号 拥有者… 属性…」）尾部，按介绍切分后去掉 6 位编号和末尾属性词；解析个数必须等于头像数，否则置空不猜；
- **一次静态请求**就能同时生成 `features_data.csv` 和填好精灵图鉴两列，不用重抓 662 个精灵页；`features` 模式只做这件事，且**不写快照**，不会影响其它表的淘汰判定；
- `update` 也会抓特性图鉴并走合并策略；`rebuild` 用已有特性表重算两列；`check` 会检查两列覆盖率。

### 技能总表（`parse_skill_catalog` / `run_skillcatalog`）
- 精灵详情页 `.sd-p-skill-card` 用 `data-*` 携带全部字段：`data-sd-p-skill`（来源-技能ID-顺序）、`data-source` / `data-type` / `data-category` / `data-level` / `data-power` / `data-energy`，效果文本在 `.sd-p-skill-description`；
- **血脉属性**：血脉卡 `.sd-p-learning` 是 `普通血脉 · Lv.15`，前半段单独存进 `血脉属性` 列；18 张血脉卡各对应一个系别，比旧模板等级列里的 `血脉·X` 更精确；
- 复用 `crawl_sources` 的精灵页抓取，不额外发请求；`skillcatalog` 模式按精灵整体替换为本次列表（抓不到的精灵沿用旧数据，避免限流清空），`update` 也会刷新并走两次缺失淘汰；
- 体检统计行数、覆盖精灵数、带血脉属性行数；wiki 已下架的精灵（页面 404）本就没有技能卡，只在成片缺失（>5 个）时报警。

### 抓取底层（`fetch` / `fetch_with_retry`）
- 默认走 `Fetcher.get(url, impersonate='chrome', timeout=20000)`；
- BWiki 限流时会返回 HTTP 200 的「**简化页**」（内容不完整），因此由调用方用 `is_ok(page)` 判定内容是否完整，失败则退避重试；
- 重试仍失败时换 `StealthyFetcher.fetch(headless=True, network_idle=True)` 兜底一次。

### 并发抓取器（`Spider`）
- `ThreadPoolExecutor` 并发（`MAX_WORKERS = 3`）+ 每个请求间隔 `REQUEST_DELAY = 0.3s`；
- 失败的页面最后改为**串行补抓**（`SERIAL_GAP = 2.0s`），避免继续触发限流。

### 精灵图鉴（`crawl_spirits`）
- 抓取「精灵图鉴」页，解析 `div.npc-card`；
- 从属性中提取 序号 / 阶数 / 进化位置 / 主副属性 / 形态 / 异色 / 赛季 等字段。
- **占位条目不进表**：wiki 上未公开的卡片（名称 `???`、`data-type` / `data-stage` 为空）由 `is_placeholder` 在抓取源头过滤，精灵表、技能表、来源表、技能石表都不会写入；`update` 读取历史 CSV 时也会清掉残留的占位行，日志会显示忽略条数。

### 技能档案（`crawl_skills`）
- 先从「技能图鉴」页解析 `div.nrc-skill-catalog-card`，取去重后的技能链接（跳过 `redlink=1`）；
- 再抓技能详情页解析属性。wiki 自 2026-11 起陆续改用 `sd-*` 模板（技能详情 `sd-s-*`：`data-sd-element` 为属性、`sd-s-stat` 为威力/耗能；精灵页 `sd-p-skill-card`、进化链 `sd-p-evo-*`），旧页面仍是 `.nrc-skill-tags` / `.roco-sk-card` / `.roco-evo-*`，解析器**同时兼容两套模板**；
- **详情页仍是增量抓取**：仅抓新增技能 + 属性为空的旧技能（约 30 次而非 ~600 次），避免全量重抓触发 wiki 限流；抓不到的技能沿用旧记录，由合并策略统一判定是否淘汰；属性仍为空（限流）的条目会在冷却后单独轻量补抓。若 wiki 改了旧技能的威力 / 描述，需要删掉 `skills_data.csv` 才会全量重抓；
- 这里**只取技能自身属性**，「谁会这招」由精灵页产出（覆盖面更全）。

### 技能来源与获取条件（`crawl_sources`）
- 逐个抓精灵详情页的技能卡：旧模板 `div.roco-sk-card`，新模板 `div.sd-p-skill-card`（以 `data-name` / `data-source` / `data-level` 属性携带全部字段），读 `data-source` 区分为 自学 / 技能石 / 血脉 / 传说；
- **获取条件的唯一正确来源**是精灵页的「图鉴课题」面板 `div.roco-quest-content > div.roco-quest-row`：
  - 只保留 `使用N次XX` 这类课题，技能名取 `.roco-quest-text` 内嵌的 `a[title]`；
  - ⚠️ 不能用 `.roco-sk-dcard` 的 `.roco-sk-source-task`，那个任务挂在别的精灵身上，会串数据。
- `parse_pet_full` 是来源表的统一出口，写表前会过滤掉 `???` 等占位的精灵名 / 技能名。
- 来源表按 `(精灵名称, 技能名称)` 建键合并，wiki 把某只精灵的血脉技能换成别的技能时，旧技能会在连续两次缺失后移除，不再永久残留。
- **字段格式统一**（`normalize_source_row`）：`来源类型` 只保留 自学 / 技能石 / 血脉 / 传说，`等级` 只放数字。旧模板曾把 `技能石` / `血脉·地` / `传说` 写进等级列，自学等级带 `LV` 前缀，现统一为 `999` / `15` / 纯数字；`parse_pet_full` 在写表前归一化，`python nrc_scraper.py normalize` 可离线修复历史数据。

### 进化链（`parse_evo_chain` / `build_evo_chains`）
- 兼容两套模板：
  - **新模板**（wiki 2026-11 改版）：`.sd-p-evo-group`（`data-sd-p-evo-branch` 标分支）下 `.sd-p-evo-chain` 是 `节点 → 连接 → 节点` 序列；节点名在 `.sd-p-evo-name-main a`（当前页为 `selflink` 时无 `title`，取文本或头像 `img[alt]`），阶位在 `.sd-p-evo-name-sub`，条件在 `.sd-p-evo-connector .sd-p-evo-condition`。隐藏分支仍写在静态 HTML 里，无需点击即可取全部分支；
  - **旧模板**：`.roco-evo-wrap` 下每个 `.roco-evo-timeline`（`data-branch` 标分支），节点 `.roco-evo-node`、连接 `.roco-evo-conn > .roco-evo-conn-pill`。
- 同一家族的完整链在任意成员页都能拿到，按家族去重（只保留一次）；`是否特殊` = 分支>1 或任一条件不是纯等级进化（突破、天气/时间、性别、技能使用、道具等附加条件都算特殊，只有 `LVx` / `LVx 进化` 为普通）。
- `update` 时若本次一个家族都没解析到（模板改版 / 全量限流），会打印警告并保留上次 `evo_chains.csv`，不会用空结果覆盖已有数据。
- 生成后按「基础名（忽略形态后缀）→ 序号」与 `spirits_data_all.csv` 对齐，补上 `源精灵序号` / `目标精灵序号`，体检改为按序号比对（消除形态后缀造成的误报）。
- 最终 `evo_chains.csv` 按 `源精灵序号` 升序（0→x）输出，家族内步骤与分支保持原有顺序。

### 合并表（`build_combined`）
- **课题（技能石）以官方「图鉴课题」聚合页（`skill_stones.csv`）为准**：按**序号（物种）一行**，技能石归属与官方页完全一致——分支形态（如 191 的「棋契陛下 / 棋祈督」）不再被拆成重复行，技能也不会被错归到其他序号；`属性` 取自精灵表的该序号主属性，`精灵名称` 取官方页的物种名。
- 因此 `combined_data.csv` 的技能石**数量与官方聚合页逐条一致**（无重复、无遗漏）；无聚合页数据时回退到「按基础名归组来源表」的旧逻辑。

### 技能石清单与交叉验证（`skillstones` / `validate`）
- `python nrc_scraper.py skillstones` 抓取 wiki 的「图鉴课题」聚合页，解析全部技能石课题，写出 `skill_stones.csv`（也是 `update` / `rebuild` 构建合并表的数据源）：
  - 数据内嵌在聚合页静态 HTML 的 `book="..."` 属性（HTML 实体转义 JSON），**一次静态请求即可覆盖全部有课题的物种**，无需渲染、无需翻页；
  - 每个物种一行（按序号 + 名称），每一条技能石课题一行；列为 `序号, 精灵名称, 类别, 条件, 奖励ID`；`类别` 固定为 `技能石`，`条件` 即「使用N次XX」，`奖励ID` 为物品 ID（含技能石本体 + 课题研究点）。
- `python nrc_scraper.py validate` 用 `skill_stones.csv` **交叉验证**主爬取（逐精灵页）的技能石课题：按序号对比两者条件集合，列出「仅主爬取有 / 仅聚合页有」的差异，有差异时写出 `skill_stones_diff.csv`，无差异则打印「未发现差异」。合并表与聚合页的一致性由体检中的「与聚合页比对」校验（2026-11-13 为 214 物种 / 504 课题，一致）。

## 注意事项

- 网站结构可能随时间变化。若某模块抓取为空，多半是解析选择器需要同步更新，可对照浏览器实际 DOM 调整。wiki 自 2026-11 起陆续把技能详情、精灵技能卡、进化链换成 `sd-*` 模板，解析器已同时兼容新旧两套；进化链整轮解析为空时会打印警告并保留上次数据，不会写出空表。
- 差异报告里的「[本次缺失]」表示这次没读到该条目（例如 wiki 下架了 `035 幽影树（突变的样子）`）；单次缺失会暂留，连续两次缺失才从表中移除。淘汰**不另存归档**，需要历史记录请自行备份 CSV。
- 清空 `.snapshots/` 等于重置淘汰计数，下一次 `update` 会按「首次运行」处理，不会删除任何记录；误删后可据此回退。
- `???` 等未公开占位条目由 `is_placeholder` 在抓取源头过滤，不会写入任何输出表。
- 来源表「等级」列已统一为纯数字（`技能石` / `传说` → `999`，`血脉·X` → `15`，`LVx` → `x`）；旧模板等级列里的血脉属性文本（如 `血脉·地`）在归一化时不保留，但已由 `skill_catalog.csv` 的 `血脉属性` 列完整收录（来源更精确：每个血脉技能一个属性）。新增记录仍追加在文件末尾（未做全表重排），如需按精灵名归位可另行排序。
- 特性两列来自特性图鉴页的「拥有精灵」反查：先全名精确、再基础名兜底。若某形态在聚合页只列了基础名，会沿用基础名的特性；精灵详情页 `.sd-p-trait` 也带特性字段，需要逐形态精确值时可扩展。
- 运行会在当前目录生成日志 `nrc_scraper_<时间>.log`（已被 `.gitignore` 忽略）。
- Windows 下中文输出已统一为 UTF-8（`sys.stdout.reconfigure`，文件用 `utf-8-sig` 写入）。
- **数据说明**：S5 部分内容 wiki 尚未更新完全（部分内容有错误），相关数据以 wiki 当前实际页面为准，待 wiki 版本更新后再同步修正。
